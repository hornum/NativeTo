# NativeTo

Учебный pet-проект бэкенда сайта для языкового обмена с носителями. Изучающие язык находят носителей
языка, который они учат, и общаются с ними в реальном времени через чат.

В проекте целился на изучение новых технологий (WebSockets, Celery, Redis, S3). А также на отработку 
продакшн-подходов в разработке (асинхронный SQLAlchemy, JWT с ротацией токенов, чат на WebSocket, фоновые
задачи, объектное хранилище, автотесты).

## Возможности

- **Регистрация и аутентификация.** JWT access-токены и ротируемые
  refresh-токены. Refresh-токены хранятся в виде хеша (SHA-256) для безопасности.
- **Подтверждение почты.** При регистрации одноразовый токен кладётся в Redis
  с TTL, а задача на отправку письма ставится в очередь Celery.
  Неподтверждённый пользователь может зарегистрироваться и войти, но не
  попадёт в чат.
- **Профиль и языки.** У пользователя есть уникальный `username`, свободно
  меняемое отображаемое имя `name` и набор языков с уровнями. Модель требует
  ровно один родной язык и не допускает дубликаты.
- **Каталог собеседников.** Подбор по языкам: твой изучаемый язык против их
  родного и наоборот.
- **Чат в реальном времени.** Личные сообщения через WebSocket, история
  сохраняется в Postgres. Поддерживается несколько подключений на одного
  пользователя.
- **Онлайн-статус.** Присутствие через heartbeat в Redis: ключ с коротким TTL
  помечает пользователя онлайн; как только сигналы прекращаются, ключ
  протухает и пользователь автоматически уходит в офлайн. Для офлайна
  отслеживается `last_seen`.
- **Аватары.** Загрузка изображений в MinIO, раздача из публичного бакета.

## Архитектура

Код разбит на слои, у каждого одна ответственность:

```
app/
  api/v1/      # роутеры — тонкие: принять запрос, вызвать сервис, вернуть ответ
  service/     # бизнес-логика (auth, users, chat, presence, avatar)
  schemas/     # Pydantic-модели для валидации запросов/ответов
  db/          # модели SQLAlchemy, сессия, клиенты Redis и S3
  config.py    # настройки из окружения (pydantic-settings)
  main.py      # сборка приложения
tests/         # набор тестов на pytest с изолированной базой
```

## Запуск

Всё поднимается через Docker Compose: Postgres, Redis, MinIO, API и воркер
Celery.

1. Скопировать пример файла окружения и заполнить значения:

   ```bash
   cp .env.example .env
   ```

2. Поднять:

   ```bash
   docker compose up -d --build
   ```

3. Применить миграции:

   ```bash
   docker compose exec app alembic upgrade head
   ```

После этого API доступно на `http://localhost:8000`, интерактивная
документация — на `http://localhost:8000/docs`. Консоль MinIO — на
`http://localhost:9001`.

Через LLM сделана простая HTML-консоль для наглядной проверки работы: `http://localhost:8000/static/index.html`.

### Переменные окружения

Полный список — в `.env.example`. Основные группы:

- Postgres: `DB_USER`, `DB_PASS`, `DB_HOST`, `DB_PORT`, `DB_NAME`
- Аутентификация: `SECRET_KEY`
- Redis: `REDIS_URL`
- MinIO: `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_ENDPOINT`,
  `MINIO_PUBLIC_URL`, `MINIO_BUCKET`

## Тесты

Набор использует отдельную базу Postgres (`nativeto_test`), подменяет
зависимость базы данных и выполняет запросы к приложению в том же процессе
через httpx. Внешние сервисы (Redis, Celery, хеширование пароля) замоканы,
поэтому тесты от них не зависят и работают быстро.

Один раз создать тестовую базу, затем запускать:

```bash
docker compose exec db psql -U <DB_USER> -c "CREATE DATABASE nativeto_test;"
pytest -v
```

Покрыто: аутентификация (регистрация, вход, ротация refresh-токена),
пользователи (профиль, языки, подбор в каталоге) и подтверждение почты.

## Как устроены неочевидные части

Несколько решений, которые не видны из списка эндпоинтов:

- **Ротация refresh-токенов.** Каждый `/refresh` удаляет предъявленный токен
  и выдаёт новую пару, так что утёкший старый токен повторно не использовать.
  Токены хранятся хешами, не в открытом виде.
- **Аутентификация в WebSocket.** Клиент отправляет JWT первым
  сообщением после открытия соединения; невалидный или неподтверждённый
  пользователь закрывается с кодом 1008.
- **Присутствие через TTL.** Статус — короткоживущий ключ в Redis, который
  обновляется активностью клиента.
  В офлайн пользователь переводится только когда закрылось его последнее
  соединение.
- **Два адреса MinIO.** Приложение загружает файлы по внутреннему адресу
  Docker (`minio:9000`), но сохраняет публичные ссылки по внешнему адресу
  (`localhost:9000`).
